# Quirks reproduced for parity, worth fixing after the flip

Companion to [go-native-generator-plan.md](go-native-generator-plan.md).
Byte parity with the C++ compiler is the acceptance criterion of every
port, so each port reproduces what the C++ generator does, including what
it does wrong. This file is the register of those findings: what it is,
where it is, what it costs, and what to do about it once the Go
generator is the reference for that language and the output may change.
Started 2026-09-21 during the tier-3a ports; add to it as ports go on.

Legend for the last column: **now** means a fix in the C++ generator can
land today without breaking parity (the Go port follows at the next
rebase); **after flip** means the fix changes output, so it waits until
the Go generator is the reference; **front end** means it belongs to the
compiler as a whole, not one emitter.

## Crashes and undefined behaviour

| Where | What | Effect | When |
|---|---|---|---|
| `t_gv_generator.cc`, `print_const_value` | Cast the constant's declared type to `t_map*` or `t_list*`/`t_set*` unchecked. A struct literal is a `CV_MAP` value over a `t_struct`, so a struct-valued constant under a container, a struct-typed map key, or a struct field whose value is a container read a `t_struct` as a `t_map`. | Segfault on 18 of 20 runs of `--gen gv lib/go/test/ConstOptionalField.thrift`; empty type names on the runs that survived. | Fixed: THRIFT-6332, [apache/thrift#3924](https://github.com/apache/thrift/pull/3924); the Go port follows it. |
| `t_d_generator.cc`, `generate_service` | Collects a service's distinct exception types in `std::set<t_type*>`, so the order of the `alias` lines that follow is pointer order. | The generated D differs from run to run for a service whose functions throw more than one exception type; no corpus file has one, so parity holds by luck. The Go port uses first-seen order. | Filed: [THRIFT-6341](https://issues.apache.org/jira/browse/THRIFT-6341) |
| `t_st_generator.cc`, `a_type` | Indexes `type_name(type)[0]` for an anonymous container, whose name is empty; `std::string::operator[]` at `size()` returns `'\0'` since C++11, so `is_vowel` is false and the article is `a`. | Defined but only by that rule; the Go port guards the empty name. Found by the oracle test on `compiler/cpp/tests/cpp/test_forward_setter.thrift`. | now: check the length |
| `t_xsd_generator.cc`, `generate_service` | Stores each exception's field type in `map<string, t_struct*>` through a C-style cast even when the type is a `t_typedef`. Works only because every reader checks `is_typedef` before touching anything struct-specific. | No visible effect today; the Go port keeps the value as `sema.Type`. | Filed: [THRIFT-6346](https://issues.apache.org/jira/browse/THRIFT-6346) |

## Output the port had to match

| Where | What | Effect | When |
|---|---|---|---|
| `t_go_generator.cc`, `generate_go_docstring_comment` | Wrote one `//` per empty doc line, including leading, trailing and doubled ones, which gofmt rewrites. | Generated code failed the gofmt check on such IDL. | Fixed: [apache/thrift#3921](https://github.com/apache/thrift/pull/3921); the Go port follows it. |
| `t_json_generator.cc`, `merge_includes` | Merges by appending the includes' declarations to the shared `t_program` objects in place. | Under `-r` the output of a program depends on which programs were generated before it; an include reached twice is written twice. Not a parity row. | after flip: merge into a copy, or a set |
| `t_json_generator.cc`, `generate_typedef` and `write_type_spec` | Writes every typedef and field type through `get_true_type()`. | The JSON cannot express a typedef chain, which is why it cannot be the front-end/emitter contract (plan §2). | after flip: emit the declared type and a `true_type` |
| `t_json_generator.cc` | Cannot render a container constant named by an identifier (`compiler/go/testdata/accept/ConstEdgeCases.thrift`): fails with `[FAILURE:generation:...]`. | Both compilers reject; the AST parity test skips the file. | after flip |
| `t_xml_generator.cc`, `write_doc` | The trailing-newline trim erases only when the backward scan breaks on a non-newline character, so a doc that is entirely newlines is written untrimmed. | An empty `<doc>` element with newlines inside. | after flip |
| `t_xsd_generator.cc`, `generate_element` | Checks `is_void` and `is_list` on the declared type, which `t_typedef` does not override, so a typedef of a list is written as a plain typed element rather than expanded. | Arguably right; documented so nobody "fixes" it by accident. | keep |
| `t_markdown_generator.cc` | Keeps its own HTML-entity escape table that overrides `t_generator::get_escaped_string`; escapes struct-field docs regardless of `noescape`; `suffix=` takes the extension without the dot and prepends one. | Inconsistent with `noescape` and with the html generator. | after flip |
| `t_html_generator.cc`, `generate_program_toc_row` | Builds the TOC maps with `std::map::insert`, which keeps the first value on a name collision. | A second declaration with the same name in the TOC is silently dropped. | after flip: warn, or key by qualified name |
| `t_mmd_generator.cc`, `emit_program_types` | Assigns `service_name_` and never reads it. | None. | Filed: [THRIFT-6346](https://issues.apache.org/jira/browse/THRIFT-6346) |
| `t_st_generator.cc`, `init_generator` | Emits every enum, and then `t_generator::generate_program` emits every enum again through `generate_enum`. | Each enum's class definition appears twice, back to back, in every `.st` file. | Filed: [THRIFT-6338](https://issues.apache.org/jira/browse/THRIFT-6338) |
| `t_st_generator.cc`, `st_class_def` | One `indent_up()` with no `indent_down()`; 26 ups and 25 downs in the file. | Everything after the class definition is indented one level deeper than the code intends. | after flip |
| `t_st_generator.cc`, `st_autogen_comment` | Writes the local clock (`%m/%d/%Y %H:%M`) into the header. | Generated Smalltalk differs from minute to minute; the golden tests pin `st.Now`, and the oracle row can flake across a minute boundary. | after flip: undated, like the Java case above |
| `t_perl_generator.cc`, `generate_service_processor` and `generate_process_function` | Four `indent_up()` against three `indent_down()` in the processor, and four against five in each process function. | Balanced only for a service with exactly one function; with more, `indent_` goes negative and the indentation of what follows drifts. | after flip |
| `t_kotlin_generator.cc`, constructor | Never sets `out_dir_base_`, the only generator that does not. | `--gen kotlin` writes into the out directory itself rather than `gen-kotlin/`. | keep; documented |
| `t_kotlin_generator.cc`, `generate_consts` | Tests `is_base_type()` and `is_enum()` on the constant's declared type, not `get_true_type()`. | A constant declared through a typedef is written as `val NAME: Type =` with no value, which does not compile. | Filed: [THRIFT-6339](https://issues.apache.org/jira/browse/THRIFT-6339) |
| `t_kotlin_generator.cc`, `generate_struct_definition` | Declares a required field's backing property under the raw field name and reads it through `kotlin_safe_name`. | A required field named after a Kotlin keyword does not compile. | Filed: [THRIFT-6340](https://issues.apache.org/jira/browse/THRIFT-6340) |
| `t_kotlin_generator.cc`, `generate_enum` | A bare `indent(f_enum);` before the member loop. | Trailing spaces after `{`, doubled for an empty enum. | after flip |
| `t_javame_generator.cc` | `generate_generic_field_getters_setters` builds its output into local streams and never writes them (`(void)out`); `get_java_type_string` and `generate_field_value_meta_data` are never called; `render_const_value` streams doubles with the default precision rather than `emit_double_as_string`; `generate_java_struct_compare_to` writes the cast line without a newline, so the next `indent()` lands mid-line. | Dead code; imprecise double constants; a mid-line run of spaces. | Dead code filed: [THRIFT-6346](https://issues.apache.org/jira/browse/THRIFT-6346); the rest after flip |
| `t_dart_generator.cc` | `generate_dart_validator` and `generate_dart_struct_tostring` test `is_enum()`/`is_binary()` on the declared type; `init_value` follows one typedef level only; `get_dart_type_string` is never called; a `tmp("_key")` in `generate_serialize_container` is allocated and discarded, advancing the counter. | A typedef'd enum or binary field skips its special case; a typedef chain gets the wrong initial value. | after flip |
| `t_lua_generator.cc` | The error texts are copied from the PHP generator: `no PHP name for base type` in both serialize and deserialize, and `cannot serialize void field` in `generate_deserialize_field`. | Misleading compiler errors only. | Filed: [THRIFT-6345](https://issues.apache.org/jira/browse/THRIFT-6345) |
| `t_d_generator.cc`, `d_reserved_words` | The entry is `"macro "` with a trailing space. | `macro` is never treated as reserved. | Filed: [THRIFT-6344](https://issues.apache.org/jira/browse/THRIFT-6344) |
| `t_java_generator.cc`, `generate_javax_generated_annotation` | Writes the local date into `@Generated(date = ...)` by default. | Generated Java differs from day to day; builds are not reproducible unless `generated_annotations=undated` is given. The Go golden tests pin the clock to 2026-01-01. | after flip: undated by default, or take `SOURCE_DATE_EPOCH` |

## Front end and command line

| Where | What | Effect | When |
|---|---|---|---|
| `main.cc`, `validate_simple_identifier` | The grammar accepts a dotted identifier (`a.B`) in every identifier position, and declarations are rejected afterwards with "Identifier %s can't have a dot." through `yyerror` and `exit(1)`; the comment says it was easier than fixing the grammar. | The error skips `failure()`, so it has no `[FAILURE:` prefix and no cleanup; the Go parser carries the same two-step check for message parity. | front end: two token kinds |
| `main.cc`, `pwarning` and `t_typedef.cc` | Warnings, and the lazily detected "Type ... not defined", go to stdout; failures go to stderr. | Warnings end up in redirected output; the audit's warnings and failures interleave unpredictably in a combined capture. The new `thrift-go` subcommands send every diagnostic to stderr; the legacy form keeps the C++ streams. | after flip |
| `main.cc`, `parse_args` | Every argument but the last is split on spaces with `strtok`; `--x` is rewritten to `-x`; `-o` writes `gen-<lang>/` under the directory while `-out` writes into it. | A directory with a space cannot be an option value; two flags a letter apart with different layouts. Kept verbatim in the legacy form; the subcommand form does not have them. | keep in legacy |
| `t_scope::add_type` and `t_type::get_true_type()` | A typedef that redefines an existing name overwrites the scope entry, so `typedef A B` followed by `typedef B A` makes each name resolve to the other. | `get_true_type()` loops forever; the compiler hangs on such an IDL instead of rejecting it. The Go front end reports the cycle. | Filed: [THRIFT-6337](https://issues.apache.org/jira/browse/THRIFT-6337) |
| `t_typedef::get_type()` | Resolves a forward typedef on first use, from the generator, and exits the process from inside a generator when it cannot. | A type error surfaces during generation, after other files may have been written. | In review: THRIFT-6333, [apache/thrift#3925](https://github.com/apache/thrift/pull/3925) |
| `t_js_generator.cc`, `render_const_value` | The `TYPE_UUID` case writes the `t_const_value*` pointer, not the value. | `GEN_UUID = '0x79b2c08980'`, a different address every run (`test/ConstantsDemo.thrift`). The Go port renders the UUID string; the oracle test skips the file. | Filed: [THRIFT-6336](https://issues.apache.org/jira/browse/THRIFT-6336) |
| `t_erl_generator.cc` | Two unpaired `indent_down()` calls (struct-literal constants, list constants) shift indentation for the rest of the file; no `uuid` case at all. | Drifting indentation after a struct constant; a uuid field fails generation in both compilers. | uuid filed: [THRIFT-6343](https://issues.apache.org/jira/browse/THRIFT-6343); indentation after flip |
| `t_haxe_generator.cc` | `generate_service_helpers` writes to a stream the content-conditional ofstream discards before dumping; `render_const_value` renders `(byte)N`/`(short)N`, which is not Haxe; `tmp("appex")` is called for a name that is never used but advances the counter. | Dead writes; invalid casts in constants. | Casts filed: [THRIFT-6342](https://issues.apache.org/jira/browse/THRIFT-6342); the rest after flip |
| `t_cpp_generator.cc` | `} else {` is joined onto the following `writeStructBegin` line in `generate_serialize_struct`; a literal `indent() + indent()` on optional setters; a stray `indent()` before `};` in `generate_service_interface_factory`. | Cosmetic. | after flip |
| `t_delphi_generator.cc`, `guid_v4` | Calls `CoCreateGuid` on Windows and does nothing elsewhere. | Random GUIDs on Windows, none on other platforms; the Go port is a no-op like the non-Windows C++. | after flip: deterministic, like the default `guid_v8` |
| `t_generator::validate_input()` | Rejects identifiers that collide with a language's `lang_keywords_for_validation()` set, wired from `main.cc`, invisible in the generator source. | Easy to miss in a port; `test/py/explicit_module/test3.thrift` (a field named `from`) is the only corpus case. | keep; documented |
| `compiler/cpp/tests/rb/t_rb_generator_functional_tests.cc` | Asserts `#  * first line` for a CRLF RDoc fixture, but the front end strips `* ` and `\r` before the generator sees them, so the compiled binary never emits that. | The test's expectation does not describe the compiler. | Filed: [THRIFT-6347](https://issues.apache.org/jira/browse/THRIFT-6347) |
| `lib/go/test/Makefile.am`, `test/go/Makefile.am` | Write filtered copies of `test/ThriftTest.thrift` into the source tree as gitignored `ThriftTest.thrift`, and `NamespacedTest.thrift`/`IncludesTest.thrift` include them. | A checkout's IDL corpus depends on whether a build has run; those files had to leave the parity corpus (`buildArtifacts` in `corpus.go`). | Filed: [THRIFT-6348](https://issues.apache.org/jira/browse/THRIFT-6348) |
| `lib/haxe/codegen/*.ps1`, `lib/netstd/Tests/codegen/*.ps1` | Sweep every `*.thrift` under the repository and expect each to compile. | Any negative-test IDL anywhere in the tree breaks two CI jobs; fixed on the branch with a directory skip list. | now |
| `main.cc`, `-audit` | Failure messages end in `" \n"` plus the trailing newline of `failure()`, so every message is followed by a blank line. | Cosmetic; reproduced. | after flip |
